# Alpha Engine · First Usable Release (Product Direction · 2026-11-13)

## 目标与发布边界

**目标不是“所有研究、认证、CI 完美”，而是让一个真实的使用者每天打开 Alpha Engine，完成有价值的研究判断。**

首要目标用户：Owner / 单操作者。主产品是 `Today → Strategies → Evidence → manual research decision`；`Research Lab` 提供下一步研究，而非历史赢利幻觉。正式投资执行仍由人负责，`research_only=true` / `trade_ready=false` 不变。

北极星指标：**Daily Research Loop Completion** —— 一次真实使用中，使用者能在 3 分钟内识别（1）今日需要看哪一个策略、（2）为什么、（3）证据与风险、（4）接下来何时复核；并把简要判断保存到自己手里。首版以 Owner 现场使用/反馈记录验证，不新增分析 SDK、用户事件数据库或云端日志。

### 两种版本，不相互阻塞

| 版本 | 要交付的真实价值 | 可用的现有能力 | 上线条件 |
|---|---|---|---|
| **Public Research Preview** | 匿名访客能立即浏览历史策略研究、图表、数据截止日和脱敏系统状态 | 已部署 Pages + formal historical evidence + static shell | 只读、清楚表明历史研究、不泄露受保护当前权重；已确认的生产匿名封锁继续保留 |
| **Owner Alpha / Daily Workspace** | Owner 登录后可以检查四策略当前可用观察、变化、理由、风险并做**人工**研究决策 | Today、Strategy Detail、Instrument、System、当前授权 reader | 现有受保护读取有效；不能声称已认证实时交易或让无权限身份读取私有数据 |
| **Certified v1** | 连续可靠运营与恢复服务承诺 | A0–A7 原合同 | 20-session/真实权限/恢复/Owner 正式签署 **后置认证**；不作为首个只读体验的功能开发前置 |

这里的“发布”意味着有一个用户可打开、可完成任务的版本；不是宣称 A7 官方正式认证已经通过。

## 唯一 P0 产品工作流

现有 `/app`、`/strategies`、`/strategies/:strategyId`、`/securities/:market/:symbol`、`/system` 已存在，**不再重做导航、图表引擎、策略注册表或算法模型**。

1. **打开 Today，立即知道看什么**。四个正式策略在一个决策优先级中呈现，最多三条当日优先查看项；分清“实际有新变化 / 合法未到期 / 证据尚未更新 / 权限不可读”。没有新闻也应给出明确的下一次观察日期。
2. **点击一条，直接看懂为什么**。落到现有对应策略 Detail 的相关 evidence/risk/decision section；必须可见收益相对基准、风险、策略事实截止日，不让用户再次搜索入口。
3. **带着结论退出，而非停留在看图**。首个功能改动应尝试一个轻量的 **“复制今日研究摘要”** 动作：从**当前已授权、已显示**的研究视图构建有日期/来源/策略/观察/风险/下一检查点的 Markdown 段落，浏览器复制到剪贴板即可。默认 public 模式仅复制脱敏历史内容。不要新增 cloud notes DB、消息系统或 PDF 渲染。若当前已有等价功能，复用而不是重复实现。
4. **下一交易日重复**。同一路径能识别上一条数据与今日的区别。最近一次成功读取不能冒充当日新观察。目的在于提高用户日常使用习惯，而不是添加更多状态 badge。

## 本地 Agent 从这个 PR 领取的功能工作

**交付 P0-1 · 首次使用闭环（先完成）**

- 从最新 main 开实际 Pages 和页面，按真实 Owner 能用的路径走一遍 Today → 一条 priority → Decision/Evidence/Risk → 复盘记录；指出最多 3 个会阻止用户完成判断的真实摩擦。切忌把完整 A0–A7 测试当成本次前置任务。
- 在原组件之上完成**一个**端到端功能垂直切片：优先补全“复制今日研究摘要”入口与数据组织；如果已有等价入口，则选实际阻塞最大的一个功能缺口，事先在 PR 留一句说明。内容必须绑定真实当前页面已获准呈现的数据、实际日期和 source；前端不重算策略/绩效/新交易建议。
- 公共匿名模式只引用已公开的历史/脱敏字段；受保护读取按原 Reader 授权；不新增后端、数据表、租户/计费或交易执行。
- 提供实际页面前后对照、有效的功能性端到端测试、1 个匿名公开路径例子、1 个已授权 Owner 使用例子（若无身份则精确标 NOT_TESTED）；不为本次文案/按钮改动跑所有训练与市场 ETL。

**交付 P0-2 · 可用版本发布**

- 对已合并且经过必要功能验证的确切 SHA 生成一个可回退的 release candidate；按现有 Pages 工作流更新 Preview 并留下浏览器直达链接。
- Owner 使用真实数据实际走一次 3 分钟研究判断闭环，记录“是否有用、哪里耽误决策、下一次想做什么”三问；不需要新增埋点服务。
- 最终在 PR 提交“发布版本 SHA / 用户获得的能力 / 一次真实使用结果 / 主要摩擦 / 下一项功能”的短报告。后续直接按用户反馈迭代。

## 排期与优先级纪律

- **NOW P0**：功能闭环 + 可点击体验 + 公共/授权范围正确。缺权限身份则先发布公开历史 Preview，不让 Owner 身份测试拖延公共已授权内容的体验改进。
- **NEXT P1**：一个真实用户反复使用后，再决定是否改善对比、导出、日常提醒或风险说明（只做最有价值的一项）。
- **PARALLEL P1 Research**：#1395 负责 Colab 长实验 sharding/checkpoint、#1389 C0 收口；新实验结果可加入 Research Lab 但不自动成为正式策略。
- **LATER certification**：#1277 的 20 日评估、#1279 真实 JWT/Edge、#1281 恢复/Owner A7 按已有问题逐步收敛；这是 **正式 v1 的服务质量认证**，不是要求在用户第一次看到价值前做完。
- 不是现在的任务：新的 UI 大改、第五策略、训练更多未证明价值的模型、为了增加 CI 数量而重构、伪造交易日或放松 RLS。

## 本 PR 合并准则

满足以下产品事实，而非形式性的文档数量：
- 真实网站可以从入口进入完整当日研究判断闭环，并且用户实际能带走一份有来源与截止日的摘要。
- 没有新增授权边界、没有泄露当前私有权重、没有把历史研究当成真实成交。
- 一条核心功能路径测试 + 对应界面实际截图/录屏通过；部署可以定位具体 SHA、知道如何撤回。
- 最终 PR 描述必须写出用户新增了哪项**可见可用能力**。如果只是把这个 brief 合并进 main 而没有实现，**不得称产品交付完成**。
