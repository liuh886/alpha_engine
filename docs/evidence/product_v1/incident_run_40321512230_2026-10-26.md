## 2. Issue 1: BYD Prospective Observations Data Chain (INC-20261026-BYD)

### 2.1 Observed Facts & Evidence
- **Job ID**: `121572409062` (`strategy (byd, ...)`), duration: 52s.
- **Requested Cutoff**: `2026-10-26`.
- **Latest Available Observation in Repository**: `data/research/byd_prospective_shadow/observations/2026-10-23.json`.
- **Exact Failure Callstack**:
  ```python
  File "scripts/refresh_byd_v1_3_formal.py", line 163, in main
    result = refresh_byd_v1_3(...)
  File "scripts/refresh_byd_v1_3_formal.py", line 70, in refresh_byd_v1_3
    byd_manifest = extend_byd_input(...)
  File "scripts/byd_formal_refresh_common.py", line 141, in extend_byd_input
    raise BYDFormalRefreshError("BYD prospective observations do not reach target cutoff")
  ```

### 2.2 Root Cause Analysis
1. **Clock & Workflow Inversion**:
   - `byd-prospective-shadow.yml` is scheduled via cron at `30 11 * * 1-5` (11:30 UTC = 19:30 CST).
   - `formal-backtest-refresh.yml` is scheduled at `30 8,23 * * 1-5` (08:30 UTC = 16:30 CST) and also triggers on any push to `main`.
   - When `formal-backtest-refresh` triggered at 12:18 UTC, CN market was closed (15:00 CST), setting CN target cutoff to `2026-10-26`.
   - However, GitHub Actions schedule queues had delayed `byd-prospective-shadow.yml`, so `2026-10-26.json` had not yet been computed or committed to `main`.
2. **Error Classification Defect in Adapter**:
   - Unlike `refresh_cn_27_v1_3_formal.py` (which catches `DataBlockedError` and exits with code 10), `refresh_byd_v1_3_formal.py` allowed `BYDFormalRefreshError` to escape uncaught, terminating with Python exit code 1.
   - `run_formal_strategy_refresh.py` mapped return code 1 to `"execution_status": "execution_failed"`.
   - In `run_formal_refresh_transaction.py`, `execution_failed` belongs to `FATAL_STATES`.
   - Instead of treating the missing prospective observation as a governed data block (`data_blocked`, which permits retaining the prior bundle and generating a `status: degraded` release), the transaction aborted with fatal error.

### 3.2 Root Cause Analysis

     `code=40203 msg=抱歉，您访问接口(adj_factor)频率超限(1次/分钟)`

2. **Fallback Provider Volume Unit Mismatch (Akshare Sina)**:
   - The router correctly fell back to `akshare_sina`.
   - Sina successfully fetched daily bars for `2026-10-26` and the overlap date `2026-10-23`.
   - However, in `scripts/data/refresh_selected_pool_prices.py` lines 778-789:
     ```python

     ...
     raise ValueError("cutoff fallback differs from governed overlap price, adjustment or volume basis: provider=akshare_sina; overlap=2026-10-23; mismatched_fields=volume")
     ```
   - Sina reported volume in shares (or lots), disagreeing with baseline historical volume by 100x.
   - Price and factor matched exactly, but because `volume` was strictly gated, valid prices were rejected as data corruption.
3. **Quarantine & Fail-Closed Protection**:
   - Subsequent fallbacks to Yahoo for CN equities were quarantined (`quarantined_yahoo_only_cn`).
   - Unresolved symbols stayed at cutoff `2026-10-23`, entering `unresolved_stale_symbols`.
