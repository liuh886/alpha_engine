# Alpha Engine 前端焕新 SPEC v0.6

日期：2026-09-09。状态：产品方向已确认；工程合同与视觉细节待开发评审。本文件不授权实施、发布或修改研究合同。

## 1. 用户已确认的决定

- 首页同时观察多条策略，首先看近期表现与交易信号。
- 信号摘要优先：增配／减配／保持，点击展开标的和目标配置变化。
- 浅色为主，克制用色、精细数字排版；支持深色主题。
- 采用多策略行式总览，保持清晰的横向比较关系。

此前聊天中的 AI 工作台概念图不是选定视觉稿；其数字、模型名、覆盖率和阻塞状态均不作为研究事实或实施依据。用户提出使用新模型能力，不等同于批准产品接入付费模型或增加 AI 助手。

## 2. 目标与边界

用户在首屏扫清各策略的近期表现、最新信号及值得关注的变化，再进入配置与证据详情。研究、数据和系统状态支持这一阅读路径。

保持 research_only=true、trade_ready=false。正式发布、证据完整、训练可用和交易资格分别表达。遵循 AGENTS.md 的当前程序、固定候选池与参考工具治理；独立策略保留自己的冻结合同。前端升级不改变因子、成本、池成员、模型参数或研究结论。

首期不接券商、不计算未经定义的多策略组合收益、不新增自动研究或 AI 推理服务。

## 3. 页面与交互

### 多策略观察台

复用 /app 作为观察入口；/strategies 保留策略目录与发现用途，避免两个页面展示完全相同的内容。其他现有深链继续可用。

顶部：关注范围、市场筛选、统一时间范围。建议默认近一月，另提供近三月、今年以来和自定义；这些默认值属于工程提案。

| 列 | 内容 |
|---|---|
| 策略 | 名称、版本、市场、证据类型 |
| 近期表现 | 小型走势、区间收益 |
| 相对表现 | 相对声明基准的超额收益 |
| 风险 | 区间最大回撤 |
| 最新信号 | 方向、调整对象 |
| 变化 | 配置未变／内部调仓／简短变化原因 |
| 时效 | 适用时点、过期或不可用提示 |

默认按关注顺序排列，无关注记录时使用注册目录顺序。筛选“有新信号”“需关注”不自动重排。关注与已读状态先作为当前设备偏好，按账户隔离，不能存入分享链接。摘要刷新后不跳动行位置。

点击名称进入策略详情，点击信号打开侧栏，两者为独立键盘可操作入口。返回恢复筛选、时间范围和滚动位置。链接记录非敏感的策略、区间和历史信号身份，不携带受保护内容。

### 策略详情和信号侧栏

详情展示完整曲线、基准、风险、信号历史，支持前后策略切换。点击历史信号关联该次配置与当时可得证据。

侧栏展示上次／本次模型目标配置、标的变化、规则或模型依据、时间边界、证据入口。侧栏关闭后焦点回到触发按钮。无法找到上次有效目标时显示“首次目标”或“缺少比较记录”，不假设零仓位。

### 其他入口

保留研究、证券、数据、资料库与系统的既有能力和深链。资料库及恢复入口不依赖研究包成功加载。首页不以数据门禁替代策略信息；某策略受阻不阻断独立策略。

## 4. 信号语义合同

方向、有效性、内部调仓和交付状态是独立维度。

| 场景 | 展示 |
|---|---|
| 有效且配置不变 | 保持 · 配置未变 |
| 总配置不变，内部变化 | 保持 · 有内部调仓 |
| 有效配置增减 | 增配／减配 + 明确对象 |
| 本期尚未生成 | 尚未生成 |
| 时效不满足策略规则 | 已过期，可查看上次记录 |
| 数据或身份校验失败 | 暂不可用 + 原因 |
| 缺访问权限 | 权限提示，不显示受保护内容 |

增减对象与口径必须由策略合同定义，不根据收益涨跌或净权重合计猜测。无法统一的策略展示原生状态名称。权重相等的容差与舍入由后端定义，不能由前端新增交易阈值。

模型目标配置不等同于用户实际持仓。现有 allocations.current 的语义需在实施前核实，不能直接重命名为“上次目标”。execution_observed 只按其证据定义解释，不能默认宣称用户实盘成交。

生成时间、数据截止时间、适用时点与下次决策时间分别表达；时效按策略节奏和交易日历判定，不用统一的 24 小时阈值。delivery_failed 不自动等于信号无效。

## 5. 表现口径

统一请求区间，标明各策略实际覆盖和截止时间，不能静默改用较短区间。回测、前瞻研究、模拟组合分开标记，不无标记拼接。

收益、超额和回撤复用已声明指标定义及计算位置，需核实净费／税费口径、基准身份、币种、复权方式、起止交易日。窗口回撤与历史最大回撤不能混标。缺失显示不可用，不补零。

小型走势使用统一起点与一致绘制规则，图形不能单独用于比较绝对风险；提供数值和文字替代。跨市场策略并列不意味着已构成组合。截止不一致时展示差异并限制误导性排名。

## 6. 工程方案与现状映射

继续使用现有 React、路由、组件和受治理产物；无需为视觉更新迁移框架。DESIGN.md 是历史架构记录，不覆盖为 UI 设计系统。视觉规范另置于前端文档。

| 现有位置 | 计划职责 |
|---|---|
| qlib-dashboard/src/pages/StrategyOverviewPage.tsx | 多策略观察台 |
| qlib-dashboard/src/pages/StrategiesPage.tsx | 策略目录 |
| qlib-dashboard/src/pages/StrategyDetailPage.tsx | 详情与历史联动 |
| qlib-dashboard/src/lib/strategy-operations.ts | 读取、校验与摘要适配 |
| qlib-dashboard/src/lib/governed-run.ts | 正式表现和运行身份 |
| qlib-dashboard/src/lib/research-bundle.ts | 本地／静态研究包读取 |
| qlib-dashboard/src/routes.ts | 保留兼容路由 |

当前 operations reader 使用 2.2.0 合同，已有状态、配置、因子证据和来源身份，但没有完整的统一方向语义。需先核查源端字段；缺失的方向、调整对象、上次目标身份与有效期通过版本化合同补充，不虚构现有接口。

当前 loadStrategyOperations 在整体读取或任何记录校验失败时将所有正式运行标为 blocked。计划区分文档级失效和记录级失效：文档版本／研究边界无效时拒绝整个来源；单条缺失或损坏只隔离对应记录；身份重复或冲突不得选择性猜测。

读取链：目录 → 轻量表现摘要和信号摘要 → 身份校验及权限过滤 → 行展示 → 按需加载详情／证据。身份包括策略、版本、运行和证据引用；缓存再区分市场、区间和权限。异步切换取消或忽略旧响应。

静态公开数据与受保护信号保持既有交付边界；隐藏 UI 不构成权限控制。不把受保护摘要打入公开静态文件。退出账户清理敏感缓存。

2026-09-08 本地预览曾出现缺研究包导致资料库仍被拦截；该观察需在实施基线重现，不能推定线上同样故障。首期包含恢复入口独立性的验证。

## 7. 视觉与响应式提案

浅色底、深色正文、单一蓝色交互强调。收益方向配色全站统一；信号方向不使用成功／失败语义。异常用文字、图标和颜色共同表达。

建议正文 14–16px，辅助信息不低于 12px，表格使用等宽数字。统一间距、列宽与小数位。字体家族、色值和行高在代表页面原型中选择，不以聊天图直接冻结。

桌面用完整表格；中等宽度收起次要字段；手机采用每策略两行摘要，展开查看风险、基准及时间。以 1440、1024、390px 验收，无全页面横向滚动。深色重新定义表面与图表对比度，保留偏好。

支持键盘导航、可见焦点、图表文字摘要、减弱动画偏好。常规文字对比度验收目标 4.5:1。首屏避免安装提示遮挡主要信息。

## 8. 实施顺序

1. 基线与合同：确认真实数据、权限、信号语义、区间指标和异常状态；输出字段映射与缺口。
2. 代表原型：观察台、信号侧栏、策略详情，包含真实／明确标注的演示数据、移动与深色状态。
3. 读取基础：摘要加载、版本绑定、局部隔离、恢复入口与缓存策略。
4. 核心页面：行式总览、筛选、详情与历史联动、偏好与深链。
5. 验收发布：契约与交互检查、访问控制、视觉和性能验收、逐页发布及回退。

各阶段按验收完成推进，当前不承诺缺少估算依据的日历工期。代码改动保持路径限定，与已有并行工作协调。产品发布与研究产物发布分开，回退 UI 不修改历史证据。

## 9. 验收清单

- 多策略首屏同时可读近期表现和信号，稳定排序。
- 保持未变、内部调仓、过期、缺失和权限不足可区分。
- 一次点击看调整，再一次到对应证据。
- 上次目标缺失不生成虚构增配；交付失败不篡改信号有效性。
- 区间变化后指标一致，实际覆盖不足明确标记。
- 一条记录失败隔离；文档级合同无效仍拒绝使用。
- 切换、返回、刷新无上下文错配；账户退出不残留受保护数据。
- 手机、键盘、深色与减弱动画模式可完成核心路径。
- 复用现有契约及 e2e 测试，新增针对上述行为的必要检查。

性能提案：在记录设备、网络、策略数量和数据大小的条件下，冷加载主要摘要 2.5 秒内可读，常规交互 200ms 内给反馈；先测基线后冻结预算。反馈时间不等于后端任务完成时间。
