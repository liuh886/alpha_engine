**项目**: alpha_engine v2.5.0

## 一、功能一：个股/组合决策引擎检验

### 1.1 当前能力矩阵

| 能力维度 | 状态 | 说明 |
|---------|------|------|
| 单股决策 (BUY/HOLD/SELL) | ✅ 可用 | `StockDecisionEngine.evaluate()` 已实现，5层决策优先级完整 |
| Watchlist 批量扫描 | ✅ 可用 | `GET /watchlist/summary` 遍历 watchlist.yaml 全部标的 |
| 买入点识别 | ⚠️ 部分 | 仅依赖 `rank < topk AND score > 0`，无技术面买入形态识别 |
| 卖出点识别 | ⚠️ 部分 | MA60 下穿 + 分数阈值 + 止损/追踪止损，缺少止盈机制 |
| 策略匹配推荐 | ❌ 缺失 | 无"给定股票 → 自动匹配最佳策略"的功能 |
| 因子归因解释 | ✅ 可用 | factor_snapshot 含 z-score/percentile，Top15 展示 |
| 风险护栏 | ✅ 可用 | 流动性/波动率/价格偏离三道硬性检查 |
| 持仓风险管理 | ✅ 可用 | PositionRiskManager 支持止损和追踪止损 |
| 中文可读理由 | ✅ 可用 | reasons 列表含 emoji 标记的人类可读说明 |

### 1.2 关键缺陷

#### P0 — 策略发现能力缺失

**问题**: 用户输入一只股票（如 AAPL），引擎只能告诉你 BUY/HOLD/SELL，但无法回答"这只股票适合用什么策略？"

**现状**: 3个策略插件（BiweeklyTrend、WeeklyQuantRating、DualLayer）各自独立运行，没有一个入口能：
- 对同一标的分别跑多个策略
- 比较不同策略对该标的的信号一致性
- 输出"推荐策略 + 推荐理由"

**影响**: 用户无法从个股出发做策略选择，只能从策略出发看个股——方向单一。

#### P1 — 买卖点缺乏时间维度

**问题**: 当前信号是静态快照（今天是 BUY），但不告诉你：
- 这个 BUY 信号持续了几天？
- 历史上类似信号出现后 N 日收益如何？
- 信号强度是在增强还是衰减？

**现状**: `StockDecision` 没有 `signal_history` 或 `signal_duration` 字段。

#### P1 — 组合级决策缺乏

**问题**: Watchlist summary 只是一个并行的逐股评估，缺乏：
- 组合层面的相关性分析
- 持仓集中度风险提示
- 多股信号冲突时的协调逻辑（如 5 只同板块全部 BUY → 是否过度集中？）

#### P2 — 模型依赖性强

**问题**: `evaluate()` 必须传入 `pred_score` 和 `rank_map`，这些来自 Qlib 训练产物 (`pred.pkl`)。如果模型未训练或训练陈旧，决策引擎输出的信号质量完全取决于底层模型的健康度——但系统没有模型陈旧性检查。

### 1.3 测试覆盖评估

| 测试文件 | 覆盖范围 | 评价 |
|---------|---------|------|
| `test_stock_decision_engine.py` | 决策逻辑、边界情况、NaN 处理 | ✅ 充分 |
| `test_position_risk.py` | 止损/追踪止损 | ✅ 充分 |
| `test_strategy_registry.py` | 插件注册、schema 生成 | ✅ 充分 |
| 集成测试（引擎+API+前端） | 端到端 | ❌ 缺失 |
| 策略间信号一致性测试 | 跨策略比较 | ❌ 缺失 |
| 模型陈旧性测试 | 陈旧 pred.pkl 的降级行为 | ❌ 缺失 |

## 三、系统需求任务清单

基于以上分析，按优先级和依赖关系整理为可执行的任务清单。

### Phase 1: 核心决策能力补全（后端）

#### T1.1 — 策略发现与推荐接口
- **目标**: 输入一只股票，输出推荐策略列表
- **范围**:
  - 新增 `POST /api/stock-analysis/{symbol}/strategy-match` 接口
  - 遍历所有已注册策略插件，对目标标的分别评估
  - 返回：`[{strategy_name, signal, confidence, reason, params}]`
  - 按 confidence 降序排列
- **验收标准**: 输入 AAPL → 返回 3 个策略各自的信号和理由
- **依赖**: StrategyRegistry 已就绪

#### T1.2 — 组合级决策接口
- **目标**: 输入一组股票（或持仓），输出组合层面的分析
- **范围**:
  - 新增 `POST /api/portfolio/analysis` 接口
  - 输入：`{symbols: [...], weights?: [...], held_positions?: {...}}`
  - 输出：逐股信号 + 组合层面指标（集中度、板块暴露、信号一致性评分）
  - 集中度检查：同板块持仓 > 40% 时发出警告
- **验收标准**: 输入 5 只科技股 → 返回"过度集中于科技板块"警告
- **依赖**: T1.1

#### T1.3 — 信号历史与趋势
- **目标**: 信号带有时间维度，支持历史回溯
- **范围**:
  - 信号持久化存储（SQLite 表 `signal_history`）
  - 每日评估结果写入，字段：symbol, signal, confidence, score, rank, timestamp
  - 新增 `GET /api/stock-analysis/{symbol}/signal-history?days=30`
  - `StockDecision` 新增可选字段 `signal_duration_days`, `signal_trend`
- **验收标准**: AAPL 的 BUY 信号已持续 5 天，趋势为"增强"

#### T1.4 — 买卖价位标注
- **目标**: 决策结果附带具体价位建议
- **范围**:
  - 基于 MA 支撑/阻力位计算建议买入区间和止损位
  - `StockDecision` 新增 `entry_zone`, `stop_loss_price`, `take_profit_price` 字段
  - 支持 ATR 动态止损
- **验收标准**: AAPL 信号为 BUY，附带"建议买入区间 185-190，止损 178，目标 205"

### Phase 2: 前端用户体验重构

#### T2.1 — 导航信息架构重构
- **目标**: 15 个页面按任务角色重新分组
- **范围**:
  - 侧边栏分为 4 个折叠组：
    - **决策中心**: Dashboard, Stock Terminal, Watchlist
    - **策略研究**: Strategy, Arena, Backtest, Compare
    - **因子研究**: Factor Analysis, Factor Registry, Experiments, Attribution
    - **系统管理**: Models, Data, Reports, Docs, Agent Center
  - 高频操作（个股分析）提升到第一级
- **验收标准**: 用户从打开页面到看到个股信号，点击次数 ≤ 2

#### T2.2 — 个股分析页面重构 (StockTerminal v2)
- **目标**: 将 Stock Terminal 从"数据展示"升级为"决策辅助工作台"
- **范围**:
  - **顶部**: 搜索栏 + 市场切换 (US/CN) + 最近搜索快捷标签
  - **核心区域**: K 线图 + 买卖信号标注（horizontal line + marker）
  - **信号面板**（优先级最高位置）:
    - 大号信号图标 (BUY/SELL/HOLD) + 置信度环形图
    - 核心理由（最多 3 条，可展开）
    - 建议价位区间
  - **策略匹配面板**: 推荐策略卡片列表（来自 T1.1）
  - **因子面板**（折叠，默认收起）: Top 5 因子 + "展开全部"按钮
  - **护栏面板**（折叠，默认收起）: 仅显示失败项，全通过则显示一个绿色勾
- **验收标准**: 非量化用户能在 5 秒内理解"该买还是该卖"

#### T2.3 — Watchlist 增强
- **目标**: 从简单表格升级为决策仪表板
- **范围**:
  - 表格增加列：当前价格、日涨跌幅、信号持续天数、推荐策略
  - 信号列使用颜色编码 (绿/黄/红)
  - 支持按信号类型/置信度/涨跌幅排序
  - 支持批量选择 → 导出/一键比较
  - 新增"信号变动"视图：只显示今天信号发生变化的标的
- **验收标准**: 用户打开 Watchlist 一眼看到"今天有 3 只新出现 BUY 信号"

#### T2.4 — 策略页面升级 (StrategyPage v2)
- **目标**: 从 YAML 编辑器升级为策略全景视图
- **范围**:
  - 保留 YAML 编辑功能（折叠面板）
  - 新增策略卡片视图，每个策略显示：
    - 名称 + 版本 + 描述
    - 关键指标：年化收益、Sharpe、最大回撤、胜率
    - 当前持仓 Top 5
    - 最近 10 笔交易记录
  - 点击策略卡片 → 进入策略详情（回测曲线、月度收益热力图）
- **验收标准**: 用户无需看 YAML 就能理解每个策略的特点和表现

#### T2.5 — 数据新鲜度指示器
- **目标**: 用户始终知道看到的数据有多新
- **范围**:
  - 全局状态栏增加：模型训练日期、数据更新日期、下次更新倒计时
  - 个股页增加：K 线数据截止日期、预测数据生成日期
  - 超过 48 小时未更新 → 黄色警告；超过 7 天 → 红色警告
- **验收标准**: 页面任何位置都能在 1 秒内感知数据时效性

### Phase 3: 工程质量加固

#### T3.1 — 端到端集成测试
- **目标**: 覆盖"API 请求 → 引擎评估 → JSON 响应"全链路
- **范围**:
  - 使用 pytest + httpx TestClient
  - 场景：正常评估、模型缺失降级、watchlist 批量、CN 市场
  - 前端：Playwright E2E 测试核心用户旅程
- **验收标准**: 核心路径 100% 覆盖

#### T3.2 — 模型健康检查
- **目标**: 引擎在模型陈旧或缺失时优雅降级
- **范围**:
  - 检查 `pred.pkl` 存在性和修改时间
  - 超过 7 天 → 返回信号时附带 `stale_model: true` 警告
  - 文件缺失 → 返回纯技术分析信号（基于 MA/RSI）
- **验收标准**: 模型文件删除后，API 不报 500，而是返回带警告的技术分析信号

#### T3.3 — 策略间信号一致性测试
- **目标**: 验证多策略对同一标的的信号是否合理
- **范围**:
  - 自动化测试：对 watchlist 标的遍历所有策略
  - 统计信号一致率（全部 BUY / 全部 SELL / 分歧）
  - 信号一致率 < 30% 的标的标记为"信号分歧"，在 UI 中特殊展示
- **验收标准**: 能自动输出"NVDA 在 3 个策略中信号一致率 100% BUY"

#### T3.4 — Walk-Forward 验证修复
- **目标**: 修复已知关键 bug — walk-forward 输出全零指标
- **范围**:
  - 排查 `src/research/walk_forward.py` 的数据管道
  - 确保 OOS 指标正确计算
  - 修复 IC 评估值异常偏高问题
- **验收标准**: walk-forward 输出非零 Sharpe 和 IC，且在合理范围内

### Phase 4: 高级能力（可选）

#### T4.1 — 自然语言策略输入 → 回测
- **目标**: 用户输入"双均线策略，5日和20日"，系统自动编译、评估、回测
- **现状**: `POST /api/strategy/compile` 已有 NL → YAML 编译能力，但未连接回测管道
- **范围**: 串联 compile → backtest → 结果展示

#### T4.2 — 实时信号推送
- **目标**: 信号变化时主动通知用户
- **范围**: WebSocket 推送 + Telegram 通知集成

#### T4.3 — 因子自然语言解读
- **目标**: 将 z-score 翻译为"动量极强，超过历史 95% 的水平"
- **范围**: `FactorSnapshot` 增加 `interpretation` 字段

## 六、总结

**StockDecisionEngine** 的核心决策逻辑是扎实的（5层优先级、4维权重置信度、因子归因），但它当前是一个"单点评估器"——能告诉你一只股票今天的状态，但不能帮你发现策略、不能追踪信号变化、不能给出具体价位。

**前端**已有 15 页的完整骨架，但信息架构平铺、核心页面（Stock Terminal）停留在"数据展示"而非"决策辅助"。最关键的问题是：**用户打开页面后不知道该做什么，看到信号后不知道该怎么行动**。

建议优先修复 Walk-Forward 数据质量（T3.4），然后同时推进策略推荐接口（T1.1）和前端核心页面重构（T2.2），这两个完成后系统就具备了"输入代码 → 看到推荐策略 + 买卖点 + 具体价位"的完整决策链路。
