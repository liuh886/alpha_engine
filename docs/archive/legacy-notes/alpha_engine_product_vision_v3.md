# AlphaEngine 产品愿景 v3.0

> 基于 2026-06-07 产品定位工作坊产出，替代 v1.0 product_vision.md

---

## 一句话定义

**AlphaEngine 是一个 Agent-native 的 Alpha 发现与归因引擎：AI agent 自主运行因子挖掘→验证→回测→归因→晋级的完整闭环，人类通过 Dashboard 审查、理解和决策。**

## 核心目标

**数据驱动地发现有效的 Alpha 因子和交易策略，获取超越 QQQ（美股）/ 沪深300（A股）的超额收益，并能解释每一个 Alpha 的来源、有效条件和衰减轨迹。**

---

## 产品定位转变

| 维度 | v1.0（旧） | v3.0（新） |
|------|-----------|-----------|
| **核心身份** | 量化研究 Dashboard | Alpha 发现与归因引擎 |
| **主要用户** | 量化研究员（人类） | AI Agent（一等）+ 人类（二等） |
| **工作模式** | 人类驱动每一步 | Agent 自主循环，人类审查 |
| **数据资产** | 临时回测产物 | 因子库 + 策略库（持久化、可复用） |
| **发现方式** | 固定 Alpha158 + 固定策略 | 动态因子挖掘 + 策略组合 |

---

## 产品原则（更新）

1. **数据驱动** — 每一个决策都必须有回测数据支撑，不接受直觉
2. **可验证** — 因子和策略表现必须可追溯、可复现、可比较
3. **风险优先** — 控制回撤比追求收益更重要
4. **Agent-first API** — 所有功能首先通过 API/MCP 暴露给 agent，Dashboard 是人类的审查窗口
5. **因子为本** — 一切策略必须可归因到具体的因子组合，拒绝黑箱

## 双重用户模型

### 一等用户：AI Agent

Agent 能自主运行完整的研究闭环：

```
假设提出 → 因子构造 → 因子检验(IC/t-stat) → 策略编译 → 回测验证 → 归因分析 → 晋级/淘汰 → 下一个假设
```

**Agent 需要的能力：**
- 通过 MCP/API 发起因子实验
- 读取实验结果并决定下一步（继续/放弃/变异）
- 自动将合格因子入库、将合格策略入库
- 记忆已尝试的假设和结果（避免重复实验）
- 生成结构化的实验报告

### 二等用户：人类（Dashboard）

人类通过 Dashboard 做的事：
- **审查**：查看 agent 发现了什么因子、什么策略
- **归因**：理解 alpha 来自哪里、在什么条件下有效
- **决策**：批准策略晋级到 PROMOTED / 竞技场
- **监控**：跟踪已部署策略的实时表现

## 核心数据资产

### 因子库 (Factor Library)

因子是系统的一等公民，不再是写死在 YAML 里的 158 个技术指标。

```
因子库
├── 原始因子 (Raw)          — OHLCV 衍生的技术指标（Alpha158 等）
├── 组合因子 (Composite)    — 多个因子的算术/逻辑组合
├── 学术因子 (Academic)     — Fama-French, Barra 等已知框架
└── 发现因子 (Discovered)   — Agent 自主挖掘出的新因子
```

每个因子记录：
- 计算公式（可复现）
- IC / IC_IR / t-stat
- 样本内外表现对比
- 与其他因子的相关性矩阵
- 发现日期、实验来源

### 策略库 (Strategy Library)

策略引用因子集合 + 交易规则 + 风控参数：

```
策略库
├── 策略模板 (Templates)     — 轮动、动量、均值回归等骨架
├── 参数化策略 (Configured)  — 模板 + 具体参数配置
└── 组合策略 (Ensemble)      — 多策略加权组合
```

每个策略记录：
- 引用的因子列表
- 交易规则（换仓频率、TopK、止损等）
- 完整回测指标
- 归因分析（收益来源分解）
- 晋级状态

## 三级晋级体系

### CANDIDATE（候选）— 自动入库

| 门控 | 阈值 | 说明 |
|------|------|------|
| IC | > 0.03 | 因子与未来收益的秩相关 |
| IC_IR | > 0.5 | IC 的稳定性 |
| t-stat | > 2.0 | 统计显著性 |
| Turnover | < 50% | 换手率约束 |

**全自动，agent 达标即入库。**

### VALIDATED（验证）— 可用于策略构建

| 门控 | 阈值 | 说明 |
|------|------|------|
| 夏普比率 | > 1.0 | 风险调整收益基础门槛 |
| 年化超额收益 | > 5% | vs QQQ/沪深300 |
| 最大回撤 | < 20% | 风险约束 |
| Walk-Forward | 通过 | 滚动窗口验证，防过拟合 |
| 多重检验校正 | 通过 | Bonferroni/FDR |
| 样本外 IC 衰减 | < 50% | 样本内 vs 样本外 |

**半自动，walk-forward 管线完成后自动标记。**

### PROMOTED（晋级）— 可用于竞技场/实盘

| 门控 | 阈值 | 说明 |
|------|------|------|
| 与现有因子相关性 | < 0.7 | 避免冗余因子 |
| 跨市场验证 | 至少一个市场通过 | US 或 CN |
| 月度胜率 | > 55% | 月度层面稳定性 |
| Human Review | 通过 | **人类审批（最后一道防线）** |

## 实验记忆 (Experiment Memory)

Agent 的记忆系统必须回答：

1. **这个假设试过了吗？** — 避免重复实验
2. **上次的结果是什么？** — 避免重蹈覆辙
3. **哪些因子有协同效应？** — 因子间交互
4. **在什么市场环境下有效？** — regime-dependent 效果

存储在结构化的因子谱系图中（factor genealogy），记录每个因子的来源、变异历史、衰减轨迹。

## Dashboard（人类审查层）

Dashboard 的目的不是「展示数据」，而是「让人类理解 agent 发现了什么」。

### 核心页面

| 页面 | 人类要回答的问题 |
|------|----------------|
| **归因总览** | "我的 Alpha 来自哪里？" — 因子贡献分解 |
| **因子库** | "Agent 发现了哪些因子？哪些在衰减？" |
| **策略库** | "哪些策略在有效？为什么？" |
| **实验日志** | "Agent 最近在试什么？结果如何？" |
| **晋级审批** | "哪些因子/策略在等我批准？" |
| **竞技场** | "已部署策略跑得怎么样？" |
| **个股终端** | "这只股票被哪些因子驱动？" |

### Dashboard 设计准则

1. **归因第一** — 最显眼的不是收益数字，而是「收益来自哪个因子」
2. **Agent 透明** — 能看到 agent 的决策过程和实验轨迹
3. **基准对比** — 每张图表都必须有 QQQ/沪深300 基准线
4. **一屏信息** — 核心指标不需要滚动
5. **操作可达** — 从看到问题到采取行动不超过 2 次点击

## 技术架构要求

### Agent-native 原则

1. **API-first** — 所有功能先通过 MCP/REST API 暴露，Dashboard 是 API 的消费者
2. **可脚本化** — 任何 agent 操作都可以通过 API 调用完成
3. **幂等性** — 重复执行同一操作不会产生副作用
4. **可观测性** — 所有 agent 操作都有结构化日志和实验记录

### 核心组件

| 组件 | 职责 | 现有代码映射 |
|------|------|-------------|
| **Factor Engine** | 因子计算、存储、查询 | Alpha158 (需重构为动态) |
| **Strategy Compiler** | NL → 策略配置 | strategy_compiler_service.py |
| **Backtest Engine** | 回测执行 | Qlib 集成 |
| **Attribution Engine** | 收益归因分解 | 需新建 |
| **Experiment Memory** | 实验记录与查询 | factor_genes.json (需重构) |
| **Promotion Gate** | 三级晋级门控 | model_service.py (需升级) |
| **MCP Server** | Agent 工具暴露 | mcp_server.py (需扩展) |
| **Dashboard** | 人类审查层 | qlib-dashboard (需重新设计) |

---

## 不做什么

- 不做实时交易（只做回测和模拟竞技场）
- 不做多用户/SaaS（先服务自己）
- 不做花哨的动画和3D图表
- 不做新闻/舆情分析（纯量化因子模型）
- 不做期权/衍生品（只做股票多头）
- 不做固定因子集（拒绝写死 Alpha158）
- 不做纯人类驱动的 workflow（agent 是一等用户）

## 路线图

### Phase 1: 因子库 + 策略库基础设施
- 重构 Alpha158 为动态因子引擎
- 建立因子/策略的结构化存储（SQLite/PostgreSQL）
- 实现 CANDIDATE 级自动入库
- 扩展 MCP Server 暴露因子/策略 CRUD

### Phase 2: Agent 自主循环
- 实验记忆系统（factor genealogy）
- Agent 可自主运行 假设→编译→回测→评估 闭环
- Walk-forward 自动化管线
- VALIDATED 级晋级门控

### Phase 3: 归因引擎
- Brinson 风格收益归因
- 因子贡献分解
- Regime-dependent 有效性分析
- Dashboard 归因可视化

### Phase 4: 自主研究 + 竞技场
- Agent 自动扫描因子空间
- PROMOTED 级晋级（含 Human Review）
- 竞技场实战验证
- 因子衰减监控与自动淘汰
