# P2-E4 RFC — 下一轮大型研究任务集（2026-11-07）

**Status: DESIGN / NOT_EXECUTABLE / NOT_APPROVED_TO_RUN.** 此文是可实施研究计划，不是现有 E2 编译器可直接加载的 JSON；不意味着真实行情、CN 执行口径、PIT、许可、独立留出集或模型能力已认证。纳入当前 [PR #1380](https://github.com/liuh886/alpha_engine/pull/1380) 的下一阶段规划，待 R1 的冷/热缓存同结果与 R2 调度小样本实测后再冻结新的 v7 数据/Runner/任务身份。**不能把 v6 的 261 个归档回执当作新代码的恢复起点。**

## 1. 核心科学问题与资源原则

> 下一轮不是“哪一个参数的验证集收益最高”，而是“哪一种结构性预测机制，在不同时间、样本、风险状态和真实成本下仍对 *相同投资基准* 提供增量价值”。

优先级：**更长且有资格的独立时间证据 ＞ 更不同的策略机制 ＞ 仓位/成本敏感性 ＞ 有节制的 HPO ＞ 更昂贵算力。** 目标计量单位为 **distinct eligible config × fold**，随机种子只有改变有效训练随机性并提供新样本差异时才进入资源预算的科学增量。Optuna/TPE 或 Hyperband 仅作为未来候选方法，当前编译器只有受约束的 seeded random search，**不得冒称已支持**。

v6 固定合同仅 4 个特征：return_5d、return_20d、volatility_20d、volume_ratio_20d；XGB、LightGBM、20 日动量、Top 5、基本 3+5 bps 与压力 10+15 bps（压力为 control，不是赢家 p06），三折 × 三种子；p06 单折对动量的配对差为 -1.66 / +5.56 / +28.39 pp，不能把独立中位数相减当配对优势。v6 `holdout prior_consumption_status=NOT_CERTIFIED`，已用过的 2026 时间窗口不能重新宣称为独立未见测试。

## 3. 策略树：研究独立经济机制，而非堆模型名字

| 模型/策略族 | 要回答的问题 | 数据输入与实施提示 |
| --- | --- | --- |
| **对照（规则与简单持仓）** | 能否超越既有最简有效策略？ | QQQ/现金参考、同一 eligible universe 等权、20/60/120 日价格动量、波动率调整动量、短期 5 日反转；相同 TopK/调仓成本，SGOV 现金对照需先核准口径 |
| **可解释线性打分** | 非线性树是否真有增量？ | Ridge/Elastic Net 等截面线性评分；模型特征严格 rolling + as-of，先解决未来 5/20 日标签与训练时序 |
| **树模型选股** | XGB/LGB 的超参数范围与不同市场期是否稳定？ | XGB/LGB 用已有 native 训练器，新增 seed 的价值须证明训练随机机制；限制树复杂度、叶节点、学习率、迭代轮数；先比较简单稳定配置 |
| **市场状态门控** | p06 是否主要依赖特定高波动阶段？ | 根据 **决策当日已可知** 的 QQQ 趋势/已实现波动、风险预算选择 full/half/cash；不能用全样本未来收益挑选 regime 阈值 |
| **组合与执行层** | 相同评分的绩效来自预测还是集中度/换手？ | Top 3/5/10、每周与每月再平衡、等权/逆波动率/有界权重、行业限额（行业标签需时间可得），真实持仓/换手 ledger |
| **未来条件特征** | 信息增益来自数据源而非超参？ | 价量 1/5/20/60/120、实现波动 10/20/60、相对 QQQ 强弱、过去突破/回撤/量能；新增财报/盈利预期/新闻仅在来源许可和 **PIT 可用时间**经过独立验证后开闸 |

**不要直接引入 LLM 预测、深度模型、复杂强化学习或 US Alpha158 合成版。** 这些并不解决当前历史样本和研究独立性不足。US Alpha158 的真实 VWAP/SIP/OTC 权利缺口仍为 BLOCKED；CN Alpha158 是否适用于新任务须从其独立质量合同确认。Qlib Alpha158 本身的表达式包含 VWAP，不能以简单 OHLC 平均替代而声称等价。

## 4. 任务矩阵（容量上限；不是已经批准的正式计划）

把 **配置×时间折** 与 **不重新拟合的成本/仓位组合评价**分开计数，避免用更高数字制造实验量：

| 层 | 赛道/内容 | 预留 config×fold 执行预算 | 资格 |
| --- | --- | ---: | --- |
| **S1 / v7-A 首发** | US-L：8 折 × 36 个候选（规则、线性、XGB/LGB；固定搜索预算），含逐折基准/风险指标 | **288** | 数据冻结并验证长区间 / R1 基础缓存可用 |
| **S2 / 扩容** | US-D：6 折 × 36 候选 | **216** | 日期动态股票池和真实历史可交易证据通过才运行；6 折数需再核验而非保证 |
| **S3 / 跨市场** | CN130：8 折 × 36 候选，独立 CN 规则/成本与基准 | **288** | CN 执行与停牌/涨跌停/买卖限制验收后才运行 |
| **S4 / 自适应 HPO** | 新增 16 个候选参数 × 6 个有资格时间折 × 两个独立市场（或不足则不填满预算） | **≤192** | S1/S3 先显示非零且稳定的配对优势；冻结搜索空间、试验序列与早停合同 |
| **S5 / 真实随机性** | 6 个确有非确定性训练来源的配置 × 4 折 × 2 个额外种子 | **≤48** | seed 有效性经过模型/输入随机路径证明 |
| **S6 / 风险后评价** | 最多 8 个 shortlist 模型 × (8+6+8) 折 × 2 个 TopK × 3 档成本 | **≤1,056 portfolio evaluations，**不是新 fits | 重用校验过的同一 score/model，成本和 TopK 不影响拟合的前提已证明 |

正式上限为 **1,032 个 config×fold 任务**（288+216+288+192+48），加 **最多 1,056 个独立的成本/仓位模拟评价**。这不是 2,088 个独立金融样本，绝不能据此计算虚假的显著性。预算按赛道设定，未过门禁的 S2/S3/S4/S5 不自动转成更多参数搜索。

**36 个首发候选（v7-A）建议组成**：8 条规则基准 + 4 个线性模型/正则配置 + 12 个 XGB 配置 + 12 个 LightGBM 配置。v6 p06 / LGB p03 作为冻结参考 challenger 加入对应模型配置集合（需要新数据/训练身份），而不是再对其污染式后验调参。市场状态门控和组合风险评价先做为 **同一预测评分的执行层对照**，不要提前产生几十套不同模型。

### S1 的时间设计

- 2021-01-04 起始历史做训练，逐步向前推进 **8 个非重叠验证窗口**；窗口建议覆盖 2023—2026 的不同宏观/AI行情阶段，但实际每个窗口的训练量、特征最长回看（如 120 交易日）及 5/20 日前瞻标签必须由数据资格检查决定，不能用日历粗分强行通过。
- 2026-11-07 以前已经看到/选择过的历史属于回溯研究，即使换窗口也是 *retrospective*，不叫新独立 holdout。**在本轮 S1 配置冻结之后新到达的真实市场数据**才可以登记为 forward OOS，且未来信息不得倒流进入历史选模。
- 特征可用 `t` 收盘之后决定，按 `t+1` 执行，不得用 `t+1` 的 OHLCV 给 `t` 打分；训练标签 [t, t+5]、[t, t+20] 的区间重叠须逐条 purge；必要 embargo 按最长相关标签决定。应记录双时间轴：决策时间与数据可用时间。

## 5. 分阶段投算力和止损

**先研究再加计算。** 不立即在 Colab Pro 开全部 1,032 项。

1. **S0 数据与研究口径准入，0 个模型任务**。冻结数据/股票池/Corporate Actions/交易可执行性/PIT/费用，验证是否可用。本阶段任何数据或身份不同都产生新批次版本，不能更改旧的 v6。
2. **S1-A 小样本 36×2=72 项**：两个相异时间折，验证每天价格/信号/成交/持仓、真实缓存命中/耗时、等权和动量基准、XGB/LGB/线性结果与原研究计量口径的可解释性。结果一致性及数据品质失败即停止。
3. **S1-B 余下 36×6=216 项**：若 S1-A 满足门禁，完成全 288 个长期历史研究任务；保留不可变 Checkpoint，归档逐日资金曲线与贡献。先读“分市场机制、逐折配对、集中度/容量”，不是先公布 48% 冠军。
4. **S2/S3 扩域**：逐个按资格门禁追加 US-D 与 CN130；不把缺失交易日内插、不合成 US VWAP、不以当下股票清单回填历史。
5. **S4/S5/S6**：仅在简单策略对照仍有稳定增量后，用 Optuna/TPE（如引入）或预声明简化 HPO；成本曲线更多通过 **复用训练好的同一评分**完成，不重复拟合。

Colab compute units 以 **可验证增量信息/单位** 衡量，配合 CPU/RAM/Cache 并行基准。建议每一阶段先设 Owner 可调整的 **Compute Units 上限/stop-loss**（首次试点可取账户余额的 5% 以内作为规划上限，而非承诺会消耗那么多），如果无可比收益/覆盖质量下降就早停。更强 GPU 只有在真实 workload 有设备原生支持且相同科学结果/费用效率改善时测试。

## 6. 下一代 scheduler 需要的任务 contract（供 Agent 实现，不是可运行 JSON）

每个 Job 必须带：

```text
  dataset_revision + source licensing + adjusted price/volume semantics
  market + universe_snapshot_asof + symbol eligibility/halts/delist
  feature_set_version + feature_availability_timestamps + label_end_times
  train_range + purge_boundaries + embargo + validation_range
  strategy_family + effective model params + actual stochastic seed
  score_id + portfolio_policy(top_k, rebalance, weights, sector, turnover limits)
  friction_schedule + benchmark + portfolio ledger schema
  runner_sha + task_key + worker CPU/RAM + checkpoint parent
  research_only=true, trade_ready=false, pit_certified=false
```

新增的 baseline / linear / regime / portfolio 类是要开发的 evaluator adapter，**当前 E2 编译器还没有实现**。新一轮 campaign 编译器要能产出 `PLANNED / BLOCKED / READY_FOR_OWNER_RUN` 但在未过门禁时不能触发训练。一个 Worker 只能提交 `task evidence`，由协调器统一检查后封存 Checkpoint；至少 1→2→4 worker 的真实测量通过才能放开并发。

## 7. 正确的研究结论形式（避免大规模 p-hacking）

每个候选必须报告：与 **同一股票池、时间折、执行约束** 的 QQQ/现金/等权/动量/逆波动率基准逐折配对后的收益差；连续日线的净收益、峰谷回撤、收益波动、真实换手与贡献集中度、行业和市场状态分层、分阶段参数漂移；已尝试参数数量及搜索后偏差。特别比较 p06/LGB p03 和其同折动量基准，而不是“赢家收益率减基准中位数”。

阶段退出不是“找到一个 50% 的胜者”，而是：**不同年份至少多数折配对净优势为正，未由极个别股票解释，执行成本下不崩溃，数据 PIT 与未来独立期间得以检验**。数值置信区间/显著性必须基于真实时序观测和依赖性设计，不能把 1,032 个 config×fold 当 1,032 个独立样本。

## 8. 建议落地次序

1. R1 冷/热缓存 **真实小样本同结果**；R2 单一写入者和 1/2/4 CPU Worker 的最小垂直切片；
2. **US-L 72 项先行**；附原始日持仓/交易 ledger、同折 paired baseline，完成后决定 216 项扩展；
3. 在不扩大风险的前提下接入 US-D point-in-time roster；
4. CN130 作为**真正跨市场**的独立策略赛道，而不是简单重复美股训练；通过后按市场单独报告；
5. 最后才投 192 项自适应搜索和 48 项真正 stochastic seed，未来未见期间独立评估，禁止默认模型/实盘晋级。

**范围约束**：不改现有 US87 v6 ZIP/Checkpoint/权利声明/私有账本；不合并 US 与 CN 训练指标为一个没有意义的总胜率；不声称新 Alpha158 US 已 ready；不假设更多 Compute Units 自然提升预测质量。
