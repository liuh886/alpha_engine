# v4.26 XGBoost ordinal risk-budget convergence result

Date: 2026-08-05  
Issue: #547  
Pull request: #549  
Decision: `xgb_ordinal_risk_budget_not_supported`

## Executive conclusion

v4.26 tested the last preregistered architecture that could reasonably convert the v4.23-v4.24 XGBoost evidence into one explicit candidate model without adding new information or searching parameters.

The experiment replaced independent adjacent-edge decisions with one four-class `multi:softprob` XGBoost model. It predicted a joint ordered risk budget across defense, bridge, core and leveraged states, then mapped the posterior expected state index to the nearest risk state.

The candidate failed. The model did not learn stable out-of-sample ordinal state timing:

- pooled macro one-vs-rest AUC was 0.4925;
- quadratic weighted kappa was -0.0117;
- macro recall was 0.2076;
- utility regret was 7.35% worse than frozen v4.2;
- only one of four outer folds had positive total utility advantage;
- the result beat only 10 of 20 label placebos;
- the 2024+ quarantine window also showed negative utility advantage and worse regret.

The posterior-expected-risk policy avoided v4.23's direct 100% cash/TQQQ endpoint selection, but it failed in the opposite direction: predictions collapsed toward bridge and core, while realized oracle states remained concentrated in defense and leveraged. This is evidence that the current 35 daily features do not identify when the correct risk budget is at either extreme.

The current daily-feature XGBoost candidate path is therefore closed. Frozen v4.2 is the explicit converged candidate model for prospective evidence collection.

## Frozen architecture

### States

| Index | State | Historical weights | Actual weights |
|---:|---|---|---|
| 0 | defense | 100% BIL | 100% SGOV |
| 1 | bridge | 50% BIL + 50% QQQ | 50% SGOV + 50% QQQ |
| 2 | core | 100% QQQ | 100% QQQ |
| 3 | leveraged | 25% QQQ + 75% TQQQ | 25% QQQ + 75% TQQQ |

### Label and policy

For every non-overlapping ten-session decision block:

1. construct the exact next-open-to-open path;
2. apply 10 bps per turnover unit;
3. compute terminal net return and maximum adverse excursion;
4. use the frozen v4.24 path utility: terminal return plus `0.50 × MAE`;
5. assign `oracle_state` to the highest-utility state, with lower-risk tie breaking;
6. fit one four-class XGBoost model;
7. calculate `expected_risk = Σ p(state=k) × k`;
8. round half-up to select the candidate state.

No action descriptors, threshold search, probability calibration, class reweighting, state deletion, feature selection, SHAP deletion or hyperparameter comparison was permitted.

### Inputs and model

- 21 market/path features;
- eight credit/duration features;
- six frozen-v4.2 state and weight context features;
- 35 inputs total;
- `multi:softprob`, depth 3, eta 0.03, 300 rounds;
- `min_child_weight=4`, subsample 0.80, column sample 0.80;
- L2 10, L1 1, gamma 0.10, max bin 64;
- four chronological outer folds with the audited ten-session embargo;
- 20 deterministic label permutations.

## Failure mechanism: middle-state compression

### Realized oracle states

| Oracle state | Blocks | Share |
|---|---:|---:|
| defense | 78 | 38.81% |
| bridge | 7 | 3.48% |
| core | 12 | 5.97% |
| leveraged | 104 | 51.74% |

### Model-selected states

| Selected state | Blocks | Share |
|---|---:|---:|
| defense | 4 | 1.99% |
| bridge | 78 | 38.81% |
| core | 114 | 56.72% |
| leveraged | 5 | 2.49% |

The realized optimum was overwhelmingly an endpoint problem: defense or leveraged supplied 182 of 201 oracle labels. The posterior expectation converted uncertainty about those endpoints into middle-state allocations.

Pooled class recall confirms this:

- defense: 2.56%;
- bridge: 28.57%;
- core: 50.00%;
- leveraged: 1.92%.

Exact state accuracy was 5.97%. Most realized defense and leveraged blocks were mapped to bridge or core. The model did not learn when to select the two economically decisive risk states.

This complements rather than contradicts v4.23:

- v4.23 selected endpoints too frequently because action descriptors and terminal-return ranking encoded an endpoint prior;
- v4.26 removed the action prior, but posterior averaging avoided endpoints almost entirely;
- neither architecture identified endpoint timing from the current information set.
